# FunPay бот: Auto SMM

Основа проекта ранее содержала автоаренду Steam, но сейчас Steam-аренда и оффлайн-выдача отключены. Основной рабочий режим — **Auto SMM** (логика из `auto_smm.py`).
Всё управление — через Telegram. FunPayAPI лежит в папке бота, внешние папки не нужны.

Текущая автоаренда работает напрямую через локальную FunPayAPI. Внешние плагины
Kosell и FunPay Universal в runtime не требуются. Совместимость локальной API
проверяется контрактным тестом `tests/test_funpay_api_contract.py` относительно
предоставленного FunPay Universal 1.18.2.

## Запуск

1. Python 3.11+.
2. Создай бота в `@BotFather` и получи токен.
3. Скопируй `.env.example` в `.env` и заполни `BOT_TOKEN` и `ADMIN_IDS` (свой Telegram ID).
4. Запусти `start.bat` (он сам установит зависимости).
5. В Telegram: `/start` → **FunPay ключ** → отправь golden_key с FunPay.

Для Linux VPS также можно использовать Docker Compose. Инструкция находится в
`README.container.md`; контейнер запускает `bot.py` вместе со всеми встроенными
фоновыми задачами и сохраняет `data`/`logs` в persistent volumes.

## Несколько FunPay-аккаунтов

- В меню **🔗 FunPay аккаунты** можно подключить до 3 аккаунтов на одного Telegram-пользователя.
- Для каждого аккаунта задаётся отдельный прокси, затем golden key. Прокси и ключ проверяются до сохранения, введённые секреты удаляются из чата.
- У каждого слота свои лоты, Steam-аккаунты, аренды и настройки Auto SMM. Кнопка «Сделать активным» выбирает профиль для управления из Telegram.
- Слоты имеют идентификаторы `<telegram_id>`, `<telegram_id>_2`, `<telegram_id>_3`; первый слот совместим со старыми данными.
- Заказы и сообщения FunPay обслуживаются независимо по каждому подключённому профилю.

## Steam-аренда

Steam-аренда, оффлайн-выдача и автоподнятие лотов отключены. Старые данные не удаляются, но новые Steam-заказы не обрабатываются.

Код доступа пользователям больше не нужен: после `/start` бот доступен всем, кроме забаненных пользователей и пользователей, не выполнивших включённую администратором обязательную подписку.

## Плагин: Auto SMM

Меню: **Плагины → 📈 Auto SMM**.

1. **Сервисы (API)** — отправь сообщение `1 https://twiboost.com/api/v2 ТВОЙ_КЛЮЧ`.
   Подходит любая панель со стандартным API v2 (twiboost, smmpanel, justanotherpanel и т.п.).
   Бот сразу проверит баланс. Сообщение с ключом удаляется из чата.
2. **SMM-лоты** — `Подписчики Telegram 1000 | 1234 | 1000 | 1`
   = часть названия лота на FunPay | ID услуги в панели | количество за 1 покупку | номер сервиса.
   Если покупатель берёт 3 шт., в панель уйдёт 3000.
3. Включи **Плагин включён**.

Что происходит:
- Покупатель оплатил SMM-лот → бот просит ссылку → проверяет домен → просит «+» (можно выключить) → создаёт заказ в панели.
- Каждые 2 минуты бот проверяет статус. Выполнено → просит подтвердить заказ. Ошибка/отмена → возврат (если включён автовозврат) и уведомление тебе.
- Команды покупателя: `чек <id>` — статус, `рефилл <id>` — рефилл.
- Заказы, не подходящие ни под один SMM-лот, обрабатываются автоарендой как раньше.

## Админ-панель

Админ-панель доступна только Telegram ID из `ADMIN_IDS` в `.env`:

- `/admin` или кнопка **👑 Админ-панель** открывает статистику, рассылку, поиск пользователей, бан/разбан и отправку сообщений.
- Рассылка копирует текст, фото, видео, документы и кнопки; заблокировавшие бота пользователи автоматически исключаются.
- В разделе обязательной подписки можно добавить публичный или приватный канал, включить/выключить проверку одной кнопкой и удалить канал.
- В разделе благодарностей настраивается токен Crypto Pay. Поддерживаются основная сеть и testnet; оплаченные счета проверяются автоматически.
- Данные пользователей, банов, подписки и донатов сохраняются при очистке рабочей базы.

## Данные

Всё хранится в `data/bot.sqlite3`: аккаунты, лоты, аренды, golden key, прокси, настройки SMM, пользователи, баны, подписка и история донатов.

## Важные переменные

- `BOT_TOKEN` — токен Telegram-бота.
- `ADMIN_IDS` — ID администраторов через запятую.
- `CHECK_INTERVAL_SECONDS` — период проверки оплаченных заказов FunPay.
- `FUNPAY_ORDER_LOOKBACK_MINUTES` — глубина поиска пропущенных оплаченных заказов после перезапуска.
